# コメント見直しの基準

`comment-cleanup`と`comment-cleanup-diff`が共通で使う。
読み込まれているコメントルール（comments.md・writing.md・言語別ルール、プロジェクトの`CLAUDE.md`と`.claude/rules/`）を正とし、ここはその適用の仕方を決める。

## 1. ルール準拠

- 名前やコードを言い換えただけのWhatは消す 型・関数・プロパティの`///`やJSDocも対象
  - 同じブロックにWhyの行があれば、その行だけ残す
  - 残した行が単独で読めないときは、意味を変えない範囲で言い回しを整える
- 区切りコメント（`// ─── 見出し ───`）、見出しだけのコメント、テンプレートが生成した定型コメントは消す
- 変更履歴や経緯（「旧: 〜していた頃」「〜するようになり廃止」）は消す
  - 残す理由がコードから確かめられるなら、理由だけにする
- 残すもの
  - Why、Why not
  - 外部の制約、回避策、数値の根拠
  - 外部データの形式・単位・コード値の意味、実測で確かめた事実、ファイルの置き場所
  - TODO
- コードと食い違うコメントは、コードを確かめたうえで直す
  - どちらが正しいか決められないものは直さずに報告する

## 2. 表現

AIが使いがちな、人が書かない言い回しを見直し、同僚に説明するときの平易な日本語にする。
次の言葉は例として挙げる。プロジェクトで別の言葉が出てきたら、同じ観点で直す。

- 曖昧な動詞: 寄せる、揃える、引き当てる、突き合わせる、潰す、成立させる、映す、担う、受け皿、合図、口、UIから外す
- 硬い漢語や俗っぽい言葉: 全断、叩く、舐める、倒す、母数、退避
- 体言止めの羅列、ナカグロ・矢印・`=`での詰め込み → 助詞を入れて文にする
- 1行に2つの内容 → 行を分ける
- 主語や指す対象が曖昧なもの、否定や条件の向きが分かりにくいもの
- プロジェクトで定着している用語はそのまま残す
- 問題のないコメントは触らない 言い換えのための言い換えはしない

## 守ること

- 意味を変えない
- 理由を新たに作らない コードを読んでも意図が確定しないものは直さずに報告する
- コメント以外は変えない 命名で補うべき箇所は報告だけにする

## 確認

- 差分がコメント行と空行だけか
  ```bash
  git diff -U0 | grep -E '^[+-]' | grep -vE '^(\+\+\+|---)' | grep -vE '^[+-]\s*(//|#|\*|/\*)' | grep -vE '^[+-]\s*$'
  ```
  コメント記号は言語に合わせて読み替える 出力が空でなければ、コメント以外の変更がないか確かめる
- 句点や英数字前後の半角スペースなど、writing.mdの表記に反するものが残っていないか
- 2で挙げた言葉が残っていないか（grepで）
- 同じ内容のコメントや用語の言い換えがファイルをまたいでそろっているか
- フォーマッタ・リンタ・テストが通るか コマンドはプロジェクトの`CLAUDE.md`に従い、推測しない

## 報告

- 直した内容の要点 before→afterは代表的なものだけ
- 確認が必要な箇所
  - コードと食い違っている疑いがあるもの
  - 推測を含めて書き換えたもの
  - 意味が読み切れず残したもの
- 命名で補えそうな候補
- 確認の結果（差分の種類、フォーマッタ・リンタ・テスト）
