md では表現できない構造（多カラム・追従目次・ソート可能な表・図）を必要とする閲覧用ドキュメントを HTML で生成する。
md が1カラム縦積み固定なのに対し、HTML は横幅とレイアウトを使えるのが採用理由。

対象外（md のまま扱う）:

- `CLAUDE.md` / `rules/*.md` / `SKILL.md` など Claude が読み込む入力。タグがトークンを消費するだけで表現力の恩恵がない
- 頻繁に更新する短いメモ。`git diff` が読めなくなる不利益が上回る

## 型の選択

最初に用途を判定して型を選ぶ。迷ったら「読み手がそのページで何をするか」で決める。

| 型 | 用途 | 読み手の動作 | テンプレート |
|---|---|---|---|
| レポート型 | 調査・分析・技術選定 | 上から読んで結論を得る | `templates/report.html` |
| マトリクス型 | 一覧・比較・進捗・テスト | 探す・絞り込む・並べ替える | `templates/matrix.html` |
| 設計書型 | 仕様・アーキテクチャ・構成 | 図と説明を往復する | `templates/design.html` |

複数の性質を持つ場合は主目的で型を選び、副次的な要素はその型の中に部品として入れる（例: 設計書に小さな一覧を含める）。

## 手順

### 1. 型を決めてテンプレートを読む

該当するテンプレート1つだけを読む。CSS と骨格をそのまま流用し、内容を差し替える。

### 2. 内容を構造化してから書く

HTML にしても、構造が整理されていなければ「見た目が綺麗な読みづらい文書」になるだけ。書き始める前に決める:

- **レポート型** … 結論を1〜2文で確定させる。これが冒頭の TL;DR になり、以降は全てその根拠として配置する
- **マトリクス型** … 列と絞り込み軸を確定させる。1行が何を表すか（1テストケース / 1依存 / 1API）を先に固定する
- **設計書型** … 図で示すものと文で示すものを分ける。図は構造、文は理由を担当させる

### 3. 出力先を決めて書き出す

共有するかどうかで置き場所が変わる。迷ったら「commit するか」で決める。

| 置き場所 | 対象 | パス |
|---|---|---|
| `docs/` | commit してチームと共有する成果物 | `docs/YYYY-MM-DD_タイトル.html` |
| `_claude/` | 自分と Claude だけが読むローカル文書 | `_claude/<category>/YYYY-MM-DD_<slug>/report.html` |

チケット本文・顧客名・システム名など機密を含むものは必ず `_claude/` 側へ置く。

- `docs/` に出す場合は `docs/assets/` への相対参照を保つため、直下に固定してサブディレクトリへ移さない
- `_claude/` に出す場合はケースごとのディレクトリ内に置き、同ディレクトリの md（調査ログ等）へ相対リンクを張る
- ディレクトリが無ければ作る

## 共通仕様

- **単一 HTML**。CSS / JS はインラインで持ち、1ファイルで完結させる
- **ライトテーマ固定**。テンプレートの CSS 変数（`--accent` 等）をそのまま使い、色を勝手に足さない
- **本文幅** … レポート型 720px / 設計書型 800px。表・図だけ `.full` で全幅にはみ出させる。文章まで横に伸ばすと逆に読めなくなる
- 見出しには `id` を振り、目次から参照する
- 文体は本文と同じく日本語。文末の句点は付ける（コード内コメント規約とは別）

## 図の作り方

**既定は SVG の直書き**。外部依存がなく、レイアウトを完全に制御できる。

SVG が向くもの:

- ノード数が10個以下の構成図
- 左右対比・ネスト・注記・凡例など、情報レイヤーを重ねたい図
- 単純な棒グラフ（データ点20個程度まで）

図の直後には必ず「この図の読み方」を添える。何を表す図かを文で補い、解釈を読み手任せにしない。

## 外部ライブラリ

SVG 直書きが非現実的な場合のみ使う。**CDN は参照せず**、出力先に応じた `assets/` に置いて相対参照する。オフラインでも開けることを保証するため。

- `docs/` へ出す場合 … `docs/assets/`。HTML は直下なので `./assets/` で参照する
- `_claude/` へ出す場合 … `_claude/assets/`。HTML はケースディレクトリ内なので `../../assets/` で参照する

| ライブラリ | サイズ | 使う条件 |
|---|---|---|
| mermaid | 3.4MB | シーケンス図 / ER図 / 状態遷移図 / ノード10個超のフロー図 |
| Chart.js | 201KB | データ点20個超のグラフ、折れ線・散布図・複合軸 |

取得例（`docs/` へ出す場合。`_claude/` なら `docs` を `_claude` に読み替える）:

```bash
mkdir -p docs/assets
curl -sL -o docs/assets/mermaid.min.js "https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js"
curl -sL -o docs/assets/chart.umd.min.js "https://cdn.jsdelivr.net/npm/chart.js@4.4.7/dist/chart.umd.min.js"
```

置いたときは併せて次を行う:

1. `docs/assets/` の場合のみ `.gitignore` に追加する（コミットしない）。`_claude/` は `~/.config/git/ignore` で除外済みのため不要
2. `assets/README.md` にライブラリ名・バージョン・取得コマンドを記録する。コミットされないファイルなので、これが唯一の復元手段になる
3. HTML 側にフォールバックを入れる。未取得時は図が消えるだけでなく、取得コマンドを画面に表示させる

```html
<script src="./assets/mermaid.min.js"></script>
<script>
  // assets 未取得でも何が起きたか分かるようにする
  if (typeof mermaid === 'undefined') {
    document.querySelectorAll('.mermaid').forEach(el => {
      el.innerHTML = '<p>図の描画に必要なファイルがありません。'
        + '<code>curl -sL -o docs/assets/mermaid.min.js "https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js"</code>'
        + ' を実行してください。</p>';
    });
  } else {
    mermaid.initialize({ startOnLoad: true, theme: 'base' });
  }
</script>
```

mermaid は IIFE 形式で動的 `import()` を含まないため、`file://` で開いても読み込める（v11 で確認済み）。

## 注意

- 型のレイアウトを崩さない。CSS を独自に足すのは、既存の部品で表現できないと判断した場合に限る
- 内容を水増ししない。セクションを埋めるために推測を書かない。根拠がなければその旨を書く
- 数値・引用は出典を確認して書く。図に数値を入れる場合も同じ
- 既存の同名ファイルがあれば上書きする前に差分の要否を確認する
- 生成後はブラウザで開いて確認する（`open <出力したパス>`）。特に表のソート・絞り込みは動作確認する
